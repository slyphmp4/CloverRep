# CloverRep 1.8.1 — Minecraft 26.3 compatibility

## Scope

CloverRep remains a **Bukkit/Paper plugin**, with no Fabric loader or Fabric API dependency.
The packaged JAR targets the **26.2 plugin.yml API floor** so it can also load on
Paper 26.2; it is compiled and tested independently against stable Paper 26.2 and
Paper 26.3 APIs. Building against the newer API does not require raising the
plugin.yml floor when the plugin still uses methods provided in 26.2.

- JDK: 25
- Gradle: 9.8.1 wrapper, checksum pinned
- Paper 26.2 API: 26.2.build.133-stable
- Paper 26.3 API: 26.3.build.255-stable
- PlaceholderAPI: 2.12.3, optional (softdepend)
- HikariCP, MySQL Connector/J, protobuf and Caffeine: shaded and relocated

No additional runtime JARs are needed for the default local YAML backend.
PlaceholderAPI is only needed for the %cloverrep_*% expansion.

## 26.3 changes

The sound helper now prefers the typed Paper registry and automatically falls
back to Bukkit's string-key sound overload if the typed registry is absent,
incomplete or otherwise inaccessible. Existing configuration values such as
ENTITY_VILLAGER_NO, BLOCK_NOTE_BLOCK_PLING and MUSIC_DISC_CAT are normalized
for that fallback; explicitly namespaced keys are preserved. A bridge can still
have incomplete sound playback, but missing Paper registry methods should no
longer break command execution solely for an error sound.

The command registration continues using Bukkit's plugin.yml mechanism:
CloverRep deliberately avoids switching to Paper-only command registration
while Cardboard compatibility is a priority.

## Automated checks

The build workflow:
1. Compiles and runs unit/integration tests against both pinned Paper APIs,
   with a temporary MySQL 8.4 service.
2. Checks the shaded plugin JAR for plugin metadata and relocated database
   dependencies.
3. Starts a **real Paper 26.3 server**, loads CloverRep, runs the console
   commands /cloverrep status and /cloverrep backup, checks for a backup file
   and requests a clean server stop.

Tests that pass on Paper are not proof of successful loading on a third-party
Fabric/Cardboard fork.

## Manual smoke tests for a Fabric 26.3 + Cardboard 26.3 server

Back up plugins/CloverRep/ and the world before replacing a live plugin JAR.
With the server stopped, replace only the CloverRep JAR in the Cardboard
plugin directory; keep the configuration and reputation.yml or MySQL data.

1. Boot Fabric 26.3 with its matching Cardboard build and Java 25.
2. Check the server log for CloverRep enabling and no linkage/classloading errors.
3. Run /cloverrep status and /cloverrep backup as an administrator.
4. Join with two separate test accounts. Run /rep + <other-player> and
   /rep - <other-player>. Verify successful votes, one-vote restrictions and
   administrator bypass.
5. With PlaceholderAPI installed, check %cloverrep_reputation_raw% on
   a player, and verify that the expansion survives a restart.
6. Restart the server and check that reputation and votes persist.
7. If enabled, inspect the below-name scoreboard for both players. Test error
   sounds and confirm no server tick-thread warnings or asynchronous Bukkit
   access exceptions.
8. If using MySQL, test /cloverrep checkdb, persistence and /cloverrep backup.

If any step fails, retain the complete server log and the installed Cardboard
build identifier. Do not publish a claim of certified Cardboard support until
these tests pass against that specific Cardboard build.
